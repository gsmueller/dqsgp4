# Derivation 007: The Matched-Pair Principle

## This Is Not a Derivation — It Is a Constraint

The SGP4 propagation model and the TLE element sets form a **matched pair**. The TLE elements were generated BY fitting observations to the SGP4 model WITH its specific constants and truncations. Replacing any component of the model with "better" mathematics, without simultaneously re-fitting the elements, breaks the match and degrades accuracy.

## Examples

### Constants

The SGP4 "wgs84" gravity model uses $GM = 398600.5$ km³/s² (= $GM_\text{GPSNAV}$), not the refined $GM = 398600.4418$. This is not an error. The TLE elements were generated assuming this value. Using the refined value would produce a systematic bias of ~1.3 m in radial position (the same bias that NGA corrected in the OCS orbit estimation process in 1994, as documented in [NGA] Sec. 3.7.1).

### G-Function Polynomials

The Hough cubic polynomial fits to the Hansen coefficients are approximations — the exact Hansen coefficients are computable via Bessel function series. But the rest of the deep space theory (the secular and periodic perturbation formulas) was derived assuming these approximate G-functions. The errors in the G-fits may partially cancel errors in the simplified perturbation theory. Replacing the G-fits with exact values, without also extending the perturbation theory, could increase total error.

### Brouwer Secular Rates

The secular rate polynomials (13, 78, 137 etc.) are from the Brouwer theory truncated at $J_2^2$ and $J_4$. The TLE generation process fits observations to a model that uses these specific truncated polynomials. Using the full Brouwer series (including $J_2^3$, $J_2 J_3$, etc.) would change the meaning of the fitted orbital elements.

## Consequence for Our Design

### Two Operating Modes

**Standard Mode (SGP4 Compatible):**
- Uses ALL original SGP4 constants, including the "wrong" ones
- These are `LegacyModelValue` — not measured, not defined, but part of the model specification
- The `accuracy` error reflects the known SGP4 model accuracy (~1 km)
- Output matches the Vallado test cases

**Enhanced Mode (Research/Comparison):**
- Uses re-derived mathematics where we have completed the re-derivation
- Uses modern constants where appropriate
- The `accuracy` error must be validated independently (e.g., against numerical integration with a full force model)
- Output will NOT match standard SGP4 test cases — by design

### LegacyModelValue

A new value category alongside `DefinedValue`, `MeasuredValue`, and `ModelValue`:

```
LegacyModelValue: A constant that is "wrong" by modern standards but correct
within the SGP4 matched-pair system. Its measurement error is irrelevant because
it's not a measurement — it's part of the model specification. Its accuracy error
is the accuracy of the overall SGP4 model (~1 km), not the accuracy of the
constant itself.
```

### How This Affects the Three Errors

For a `LegacyModelValue` like $GM = 398600.5$:
- $\sigma_m = 0$ — it's not a measurement, it's a specification
- $\delta_p$ = representation error in type T
- $\delta_a$ = SGP4 model accuracy (~1 km equivalent, propagated through the formula)

The "measurement error" in the traditional sense ($398600.5 \neq 398600.4418$) is part of the model accuracy, not the measurement uncertainty.

## What This Means for the Derivations

Derivations 001-006 (geometric and physical constants of the equipotential ellipsoid) are clean: they derive quantities from the four defining parameters using exact formulas. No matched-pair issues.

The matched-pair issue arises in Derivations 008+ (Brouwer theory, SGP4 propagation) where every constant and every truncation is part of the model specification. In those derivations, the `accuracy` error will be nonzero and will dominate the error budget.
